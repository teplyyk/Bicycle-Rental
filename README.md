# Етап 1. Іменники й дієслова (Проєктний аналіз)


Іменники (Сутності системи): велосипед (номер, тип), клієнт (ім'я, баланс), станція (назва, список великів), менеджер поїздок (загальна виручка), поїздка (хвилини).
Дієслова (Дії та методи): отримати тариф, додати велосипед, видалити велосипед зі списку, списати кошти, обробити поїздку, вивести звіт для адміна.


# Етап 2. КАРТА КЛАСІВ


1. Class Bike (Файл bikes.py)
Що знає (Атрибути): number: str (номер), is_electric: bool (тип: електро чи звичайний).
Що вміє (Методи): get_tariff() -> int (повертає ціну за хвилину залежно від типу: для електро дорожче, для звичайного дешевше).
2. Class Station (Файл bikes.py)
Що знає (Атрибути): name: str (назва станції), bikes: list[Bike] (динамічний список великів, які зараз припарковані на цій станції).
Що вміє (Методи): add_bike(bike: Bike) -> None (приняти велік на станцію), remove_bike(is_electric: bool) -> Bike | None (забрати зі списку велік потрібного типу та повернути його об'єкт, якщо такого типу немає — повернути None).
3. Class Client (Файл client.py)
Що знає (Атрибути): name: str (ім'я), balance: float (рахунок грошей).
Що вміє (Методи): charge(amount: float) -> bool (зняти суму за поїздку; повертає True, якщо грошей вистачило, або False, якщо баланс замалий).
4. Class RideManager (Файл rides.py)
Що знає (Атрибути): total_revenue: float (загальна виручка всієї мережі прокату).
Що вміє (Методи): process_ride(client, start_station, end_station, is_electric, minutes) -> str (головний керуючий клас: забирає велік зі старту, рахує ціну через тариф, списує гроші у клієнта, додає касу в total_revenue та паркує велік на кінцеву станцію).

ЕТАП 3 (Частина 2). Покроковий план функції main()
1. Створення об'єктів: Ініціалізувати дві станції (Центр, Парк), розкинути по них кілька великів разных типів та створити клієнтів із грошима на рахунку.
