Етап 1. Іменники й дієслова (Проєктний аналіз)
Іменники (Сутності системи): велосипед (номер, тип), клієнт (ім'я, баланс), станція (назва, список великів), менеджер поїздок (загальна виручка), поїздка (хвилини).
Дієслова (Дії та методи): отримати номер, отримати тип, отримати вартість, додати велосипед, видалити велосипед зі списку, списати кошти, обробити поїздку, вивести звіт для admin.
Етап 2. КАРТА КЛАСІВ
1. Class Bike (Файл bikes.py)
Що знає (Атрибути): number: str (номер), is_electric: bool (тип: електро чи звичайний).
Що вміє (Методи): get_number() -> str (повертає номер), get_is_electric() -> bool (повертає тип велика), get_bike_cost() -> int (повертає ціну за хвилину залежно від типу: для електро дорожче, для звичайного дешевше).
2. Class Station (Файл station.py)
Що знає (Атрибути): name: str (назва станції), bikes: list[Bike] (динамічний список великів, які зараз припарковані на цій станції).
Що вміє (Методи): add_bike(bike: Bike) -> None (приняти велік на станцію), remove_bike(is_electric: bool) -> Bike | None (забрати зі списку велік потрібного типу та повернути його об'єкт, якщо такого типу немає — повернути None).
3. Class Client (Файл clients.py)
Що знає (Атрибути): name: str (ім'я), balance: float (рахунок грошей).
Що вміє (Методи): charge(amount: float) -> bool (зняти суму за поїздку; повертає True, якщо грошей вистачило, або False, якщо баланс замалий).
4. Class RideManager (Файл rides.py)
Що знає (Атрибути): total_revenue: float (загальна виручка всієї мережі прокату).
Що вміє (Методи): process_ride(client, start_station, end_station, is_electric, minutes) -> str (головний керуючий клас: забирає велік зі старту, рахує ціну через тариф, списує гроші у клієнта, додає касу в total_revenue та паркує велік на кінцеву станцію).

ЕТАП 3. Розподіл файлів та ролей у команді

Роль 1 (Аня): Файл station.py — відповідає за усе, що стосується станцій.
Роль 2 (Маша): Файл clients.py — відповідає за усе, що стосується клієнта та його балансу.
Роль 3 (Ярослава): Файл bikes.py — відповідає за усе, що стосується велосипедів та логіки поїздок.
Роль 4 (Маркіян): Файл main.py — відповідає за головний запуск програми, демо-дані, звіти адміністратора та перевірки assert.
ЕТАП 3 (Частина 2). Покроковий план функції main()
1. Створення об'єктів: Ініціалізувати дві станції (Центр, Парк), розкинути по них кілька великів разных типів та створити клієнтів із грошима на рахунку.
2. Успішні катання: Запустити 2–3 симуляції нормальних поїздок між точками через метод process_ride(), щоб гроші списалися, а велики переїхали на інші станції.
3. Перевірка помилки (Демонстрація обробки помилок): Змоделювати ситуацію з помилкою (наприклад, спроба взяти електровелік, коли на станції залишилися лише звичайні). Програма повинна акуратно повернути статус помилки текстом, а не зламатися.
4. Автоматичні тести: Перевірити правильність фінальних балансів людей та загальної виручки мережі після поїздок через конструкції assert.
5. Финальний звіт: Вивести гарний текстовий звіт для адміністратора: скільки великів зараз на кожній станції та скільки всього заробила мережа.
